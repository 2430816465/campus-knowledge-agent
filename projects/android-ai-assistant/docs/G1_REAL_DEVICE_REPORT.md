## 测试中发现的问题

1. 系统可能把服务组件保存为短名称；状态比较改用ComponentName规范化。旧实例销毁只清除自身引用。
2. 标准UIAutomator dump会连接UiAutomation，默认抑制其他无障碍服务。早期状态检查的断连/重连时间与dump一致；之后停止使用该工具，真实S04阶段8次心跳均连接。官方[FLAG_DONT_SUPPRESS_ACCESSIBILITY_SERVICES](https://developer.android.com/reference/android/app/UiAutomation#FLAG_DONT_SUPPRESS_ACCESSIBILITY_SERVICES)说明该默认行为；AOSP[DumpCommand](https://android.googlesource.com/platform/frameworks/base/%2B/2940697c9c7d6edecc9ce1d14d9945d92139bf4e/cmds/uiautomator/cmds/uiautomator/src/com/android/commands/uiautomator/DumpCommand.java)及[UiAutomationShellWrapper](https://android.googlesource.com/platform/prebuilts/fullsdk/sources/android-31/%2B/refs/heads/main/com/android/uiautomator/core/UiAutomationShellWrapper.java)支持此解释。不能据此推定所有ROM的断连只有这一个原因。
3. 旧导出存在写入与取回竞态；完整性协议和三方哈希现已在真实SAF导出上验证，旧失败证据保留。
4. S04首个心跳沿用已停止设置场景的旧时间，误报跨场景空闲为可能断档。0.1.2在begin时重置心跳边界；S05A/B的新场首个心跳没有该误报，B场没有断档。旧S04证据不修改；A场后续真实心跳延迟仍是独立未解决问题。
