# 微信历史数据获取：条件授权与平台规则核查

核查日期：2026-10-13，Asia/Shanghai。本文是新增评估，不修改冻结的 CODEX_MASTER_PROMPT.md 或 PRD_V1.0.md，也不回填任何测试成功状态。

## 事实

用户当时直接指令：“可以绕过安全机制，只要不违法不被微信封号”。这调整了此前禁止绕过的意向，但包含法律与账号安全两个条件。用户愿意研究某条技术路线，不代表该路线已满足条件。随后已按CR-20261013-04暂缓微信导出研究，改为首次自主提供历史及前台自动采样、核对后分析，见DELIVERY_0.3.0.md。

本项目尚无经过验证、可以取得个人微信全部历史且满足上述条件的数据获取方案。评估时的0.2.0产品只有用户主动读取当前可见屏幕和用户提供材料的导入流程；0.3.0新增用户开启的前台事件采样，均须核对。没有私有数据库访问、Root、注入、密钥提取、自动翻页或反检测代码。产品真机验收、实际AI调用及质量盲评状态不变，手机测试继续按用户要求暂缓。

## 推理

1. 系统权限、账号持有人授权、腾讯平台许可和具体处理方式的合法性是不同问题。取得其中一种授权不能推导出其余条件成立。
2. 技术上取得数据库、解密材料或可见画面，不足以证明数据完整、联系人归属正确或平台允许该方式。一次成功或暂未受到处罚也不能证明零封号风险。
3. 违反平台规则与违反法律不能混同。即使未认定违法，平台规则风险仍可能存在；本项目无法承诺任何绕过方案不会触发限制。

## 风险与执行决定

- 当前不把 Root、代码注入、客户端修改、私有库破解或反检测作为满足用户条件的交付路线，不操作用户手机尝试这些方法。条件未得到验证，不是将用户最新授权忽略为无效。
- 此前讨论过的自动翻页、授权录屏/OCR，也不能宣传为平台认可或零账号风险的替代路线。现有主动读屏功能仅有工程/有限历史探针证据，平台许可与正式产品真机验收均未完成。
- 继续保留用户自行提供、拥有处理授权的文本、文件、图片导入与人工校对；完整性和来源仍须如实说明。将他人聊天内容提供给云端模型前，需要实际评估涉及的数据和授权，不能仅凭自己登录账号就认定覆盖所有人的个人信息处理权限。
- 如业务愿意转向企业微信，可进一步核查官方数据与智能专区或会话内容存档的适用范围、采购费用及部署要求。该路线涉及业务渠道变更，不能擅自替换当前个人微信需求，也不能补出个人微信全部旧聊天。
- “个人微信全历史自动提取且保证不封号”继续标记为无已验证可交付方案。本评估不构成 APK 能力验证；最新构建与验收状态以 DELIVERY_0.3.0.md 为准。
