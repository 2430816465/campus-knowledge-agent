## 1. 冻结产品要求——必须原样实现或标注为未通过

**定位：** 给少数颜值/聊天主播在微信私聊时提供 AI 军师建议。每位主播拥有完全独立的数据、聊天风格及观众档案。初期单台 Android 手机，本机使用；iPhone 之后实现，Windows 辅助，暂不强制跨端同步。

**推荐回复：** 由主播主动点击“生成推荐”才调用模型；根据当下情境动态生成不同数量的候选，允许每个候选由一条微信消息或连续多条短消息组成；不限制字数、标点、错别字、空格、Emoji、拆分方式，尽可能严格模仿此主播历史中本人真实发送消息的风格；候选根据主播风格、上下文、真诚与自然度、情绪回应、误会风险综合排序。允许提示“不必回复”。可建议新的话题，但不强制延续聊天。

**主播独立操作：** 软件只展示建议、完整分析和可供主播手动参考的消息分段；主播自行选择、调整、打字、发送。**绝不自动填入微信输入框、绝不代发**。对用户最终确实发送的回复，优先通过可靠的界面读取补充记录，读取不到时手动确认；不得把未采纳候选当作已发送话术。

**全部历史：** 每位观众当前可能少于 1000 条，但未来持续增长。初次导入重点支持手机微信的多张截图 OCR 去重排序、分批复制文本，允许人工核对；不依赖电脑有完整历史。保存已取得的双向消息：稳定联系人 ID、主播 ID、发言人、内容、时间、顺序、类型、来源和校验状态。各观众严格隔离；昵称重名或变更时须由主播核对。新观众没有任何标签也能直接生成高质量回复；标签由 AI 建议、主播确认，支持人工增删改。保存矛盾历史事实及其时间与依据，不擅自覆盖原记录。

**真正全量理解：** 如果所选生成模型的上下文窗口能够容纳，就在每次生成时按时间顺序提供该观众的全部可用文字历史、主播风格资料及必要的多媒体转写/描述；不能只看最近 20 条。若超限，应先分批通读构建有原文证据的结构化记忆，再回查相关原文并合成；记录本次实际处理的消息数、覆盖范围、超限与缺口。重要推断应能点回对应消息。不可虚称看完未取得的消息。

**媒体：** 文字、Emoji、图片、语音、表情包及主动导入的其他聊天材料均建立关联记录。可获得原件时保留引用并在必要时回查；否则从截图或转写中提取说明，无法识别时标记未知，不臆造音视频细节。

**AI 全流程：** 生成模型可以切换（例如 DeepSeek / OpenAI 兼容接口，具体按已验证文档适配）；Jev 为结构化辅助决策，默认开启并可配置；狗头军师 Skill 和恋爱大师 Skill **默认均开启，综合之后给出候选**，两者也能独立开关。Jev 不负责直接写长篇回复；Skill 是知识和流程指令，不要假定它们天然具有独立在线 API。要保留不同分析视角的结论与矛盾，显示完整分析报告（默认折叠）：事实/推测/未知、情绪线索、历史证据、关系变化、不同解释、每条候选理由、误解风险、下一步建议。简单回复也按用户要求使用默认启用组件；某组件调用失败必须明确显示状态和原因，不得静默跳过并宣称完整运行。第三方 Skill 的原始使用边界、版权和许可必须先核对。

**学习风格：** 优先从全部真实的主播历史消息学习用词、长短、句式、标点习惯、表情、分段、口头禅和语气；可选精选样本增强；持续学习主播经确认的真实发送文字。不得学习观众的内容冒充主播风格；不得将 AI 生成但未发送的内容当作训练样本。允许保留主播独特错别字/口语，但不能据此编造共同经历、感情承诺、诊断或突破明示边界。

**用户体验：** Android 原生 UI：悬浮球、底部候选面板、完整独立 App；观众管理页、标签、历史导入与校对、完整军师报告、API/模型/组件设置、费用页。自动收录与主动触发生成必须隔离；连续发消息可先自动收录，主播按按钮才统一分析。

**预算和优先级：** 每日预计 10—30 轮生成。质量优先，可以接受较长响应时间；月 API 预期 30—100 元人民币。到 100 元时提醒并要求主播明确确认才能继续使用付费调用；不能靠私自缩减上下文或关闭默认组件隐瞒费用。

**关系边界：** 以让对方开心、感到被认真对待、减少误会为主要目标，适度延伸话题；暧昧尺度结合真实关系和主播对特定观众的设置，不编造亲密关系、不做虚假恋爱承诺、不诱导打赏、不利用脆弱性操控对方。避免将心理推断包装成已确定事实。

**绝对硬要求 P0：** 指定 Android 真机中，软件要自动收录微信后续所有新消息，包含微信不在前台、没有通知、未进入聊天页查看的消息；消息识别验收目标 **100% 零遗漏、零错人、关键内容零错误**。这是不可降低的产品验收条件，**但尚未证实普通第三方 Android 应用在微信隔离机制下能够实现**。Android 先做一款真机：用户口述“红米 K80 游戏版”，实际型号、Android/HyperOS 和微信版本必须从设备设置和 ADB 读取核对，不得自行推定。

**验收：** 100 组覆盖典型真实授权或合成聊天案例，至少 95 组满足预先制定的全部可用条件；同时做同一输入的“普通生成模型 vs 默认 Jev+双 Skill 完整系统”匿名对照测试并报告结果，不预设多组件必定更好。

## 4. P0 / G1：优先研发并实测微信自动收录，不得跳过

先交付一个独立的 **Android 微信消息可观察性验证 APK**，避免在最关键能力未确认前投入完整 AI 界面。

建议 Kotlin + Jetpack Compose + Room，模块化设计：
- 合规的 `AccessibilityService` 可见界面事件和文本提取；
- 经明确授权的 `NotificationListenerService`，记录有通知时收到的内容；
- 遵守 MediaProjection 逐次/逐会话用户授权机制的本地 OCR；必要时评估无障碍截图 API；
- 联系人、方向、时间、顺序、来源、消息正文和检测结果的标准化结构；
- 相同消息多通道去重，但同一联系人连续发送内容相同的两条消息不可误去重；
- 设备休眠、被系统终止、权限撤销、微信更新、网络变动时明确记录采集断档；
- 前台展示可观察事件、权限状态、识别率、人工独立真值对照结果的调试页；
- 详细报告哪些字段根本不可观察。不要绕过系统安全保护。

使用独立发送端的实际发送日志作为集合 G，自动收录且联系人、方向、正文和顺序正确的消息作为集合 A，**只以 G 为分母**。截图手动补录不能充当自动收录成功；OCR 拿到当前可见文字不能充当此前未打开消息已被收录。至少覆盖：
1. 微信前台，正在看单聊；
2. 当前会话快速连续文本、相同文本重复发送；
3. 切换多个联系人、相同昵称；
4. 微信后台，有通知；
5. 微信后台，关闭通知或该联系人消息免打扰；
6. 从未打开对应聊天对话；
7. 锁屏、系统休眠、内存回收/杀后台、系统重启；
8. 断网重连，跨时段积压的新消息；
9. 文本、Emoji、图片、表情、语音、引用、撤回及异常消息；
10. 权限取消后恢复、微信版本或窗口结构变化。

对每种情况制作真实测试步骤、原始真值清单、自动收录日志、错漏对比表，输出 `docs/G1_P0_REPORT.md` 和可复现实验脚本。对未能在开发机远程执行的真机操作清楚列为“需用户手机操作/待测试”，不得用模拟器或 Mock 成功代替真机成功。有限场景零遗漏只能写“在这些场景零遗漏”，不能宣称普遍或永恒 100%。

**硬性停工闸门：** 若普通授权路径不能取得“无通知＋未打开会话”的真实消息，就把 G1 判定为不通过或无法证实，明确列出架构限制与证据；**停止进入 G2～G6 的完整产品开发**。可整理替代选项给用户比较，但不能自行切换到手动方案、Hook、注入、破解数据库、root 等高风险方案，也不能声称核心目标完成。没有用户明确改变需求就保持停工状态。若未连接实机也不得通过闸门。

## 5. 仅在 G1 有可靠证据通过后，继续实际开发

### G2 历史与观众记忆
- 设计 `Account/Streamer/Contact/Message/MediaAsset/Tag/Fact/Conflict/Evidence/ImportBatch` 模型，稳定键与严格隔离。
- 实现多图截图 OCR、时间顺序整理、重叠去重、说话人核对、原图/原文追溯、文本导入、缺口标记和人工纠错。
- 新观众无标签直接开始聊天；AI 只提出标签建议，主播确认后生效。
- 支持主播手动补录、更新和纠错；未取得的微信历史必须标记未知。

### G3 AI 引擎
- 模型接口可切换，通用流式/非流式支持、超时重试、限流、规范化错误和 token 计价；不得把模型适配器 Mock 说成真实 API。
- 默认 Jev 开启 + 狗头军师开启 + 恋爱大师开启；各自可配置。首次启用时展示组件用途与已知局限；Skill 使用方式应符合许可与来源要求。
- Jev 输出只做结构化辅助分类和策略比较，不能把分值或概率伪装成对观众真实心理的确定预测。
- 综合两个 Skill 的分析视角和现实证据后由生成模型撰写结构化多候选 JSON，校验输出完整性、长度可变、分多条消息、候选排序、可选“不回复”与新话题建议。
- 分析页可追踪历史证据、事实/推测/未知；要防止聊天记录内的提示注入文本影响系统指令。
- 如 API 或 Skill 失败，显示错误及禁用/回退前所需的用户选择，不允许偷偷跳过组件。

### G4 风格学习和 UI
- 从所有已确认的主播历史消息提取可复现的格式、长度分布、标点概率、口头禅、消息拆分分布、表情用法；可选精选范例，不把新观众的话混入。
- 悬浮球 + 底部面板 + App 完整页，材料导入与人工校对页、账号切换、观众档案与标签、长报告、模型与组件设置、预算页。
- 允许主播逐条查看不同候选消息组，并手动选择、参考、编辑、打字发送；绝不自动操作微信输入框或自动发送。
- 后续真实已发消息的采集/人工核对单独入库。切换联系人应取消并清除旧联系人的生成结果，确保不串人。

### G5 稳定性、安全底线、性能
- 真机与自动化测试覆盖权限被撤销、系统休眠、OCR 识别错误、同名观众、长上下文超限、网络断连、API 错误、月费达到100元后提醒并要求确认。
- 尽量本地加密存储、Keystore 保管密钥、最小权限、可删除数据；这些属于基本安全要求，不需开发复杂的权限管理平台。保证不将私聊和密钥输出到公共日志。
- 记录每一轮实际使用的完整历史条数/缺口、模型版本、Skill启用情况、token与费用；不得为省钱暗中减少历史、改变默认组件。

### G6 正式质量验收
- 构建 100 组已授权或合成测试聊天。每组都检查：①至少一条推荐可直接用或轻微修改；②不编造共同经历/串观众；③正确利用关键历史；④形式和表达贴近主播习惯；⑤尊重真实边界。**五项同时成立**才认定该组通过，目标≥95/100。
- 同一历史、同一问题，普通 LLM 与完整三组件系统匿名混排由主播评分，汇报可用率、偏好率、优势与劣势；不得杜撰评分。
- 含“第35条偏好、第410条误会、第899条追问”型长程测试，核查最早/中间/最近历史证据及引用准确性。含新观众零标签、多媒体、连续发送和多主播隔离情境。
- 验收必须分别标注：代码存在、单元测试通过、模拟器通过、真机通过、真实微信通过、完整 P0 通过；不能混成一句“全部完成”。
