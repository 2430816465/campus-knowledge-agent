# 原生存档、迁移与恢复

## 实际存放位置

游戏在 Godot user://saves 中保存本机档案。默认 Windows 路径为 %APPDATA%\Godot\app_userdata\洪荒众仙府 · Godot\saves；Linux 为 ~/.local/share/godot/app_userdata/洪荒众仙府 · Godot/saves。如果启动时覆盖 XDG_DATA_HOME，Linux 路径随设置变化。通过“事务 → 设置”的文件对话框可导出到自选位置。

普通档为 normal.json。四类隔离展示档使用独立文件。模拟账号、分区、虚拟设备组合使用独立哈希文件名，不能覆盖普通档。模拟服务另存 mock-online-v1.json；它只在本机工作，没有真实联网。

## 保存保证与边界

- 数据载荷仍是兼容迁移后的 V3；原生信封为 honghuang-xianfu-godot 版本1，含 SHA-256 校验。
- 经济命令先在副本执行，验证资产、规则、事务记录后写临时文件，flush、回读核对，再替换。Linux同文件系统使用原子rename；Godot Windows实现存在删除旧目标后移动新文件的间隙，因此用预先保留的有效备份和启动时中断检测保护恢复。成功保存后界面才能显示永久获得。主文件缺失但备份仍在时，禁止初始化空档，必须明确恢复或导入。
- 保存失败保留原内存、资产和随机序列。再次尝试不能重掷已提交的结果。
- 更新有效档前保留 .backup。坏档不会静默改成空档。
- 原子创建目录取得唯一写入权，并检查磁盘指纹和修订号。另一窗口只读，须关闭原窗口再重新载入。活跃进程不会因暂停、长帧或15秒超时失去写入权。
- 崩溃令牌确认原进程已结束后可回收。Linux 查询本地 /proc；Windows 用系统 tasklist 查询整数 PID。查询不可靠、锁损坏或未知平台时宁可只读，不冒险覆盖。
- 保证针对本机可靠文件系统，不是跨电脑共享磁盘分布式锁。文件校验不是防作弊签名，本地模拟回执不是可信支付凭证。

## 从旧 Canvas 版迁移

1. 在旧游戏中导出 JSON。原生 Godot 无法自动读取浏览器 localStorage。
2. 先导出当前 Godot 档案作为额外备份。
3. 在“事务 → 设置 → 导入存档”选择旧 JSON。
4. 验证 V1/V2/V3 信封、FNV 校验和数据后迁移；失败保留原文件与当前档，不发升级补偿。
5. 原始导入文本另存 .import-original-时间.json，当前有效档按正常规则备份。旧角色、培养、库存、保底和已领奖历史不重算。

测试使用旧引擎实际导出的 V1/V2/V3 副本及工程自带测试档，不声称取得用户当前浏览器真实游玩档案。常驻池按用户要求改为三稀有度角色池，旧资产和抽取历史保留，差异见经济说明。旧代码不保证读取新装备、模拟账号和50人档案；回退须同时用与旧代码匹配的备份。

## 损坏恢复

设置页提示只读、错误与可用备份。选择恢复前会说明失去备份之后的进度。当前文件另存 .before-restore-时间.json。也可导入自己另存的有效 JSON。

写入权异常时先正常关闭其他窗口再重启。不要在多个窗口仍运行时删除锁。若异常退出后仍只读，关闭全部游戏进程，完整复制存档目录，再移走对应 .writer-lock 目录；保留 JSON 和备份。系统复用进程号时宁可暂时只读，不覆盖进度。

## 隔离与模拟账号

展示档只能在设置中明确进入和重置；独立时钟只作用于展示档，不改系统时间。展示档不能导入普通档。模拟账号档仅同账号、同分区使用，虚拟设备各有本地缓存。云档下载须明确处理冲突；选择云端也不能覆盖本窗口尚未看见的新磁盘修订。

沙盒订单先向本地模拟服务查询已支付回执，再由游戏原子提交资产与已领取ID。界面奖励数字不作凭据。写盘失败可重试，重复回执只到账一次。普通档不收模拟付款奖励。真实身份、服务端结算、跨物理设备同步及支付未接入。

- tests/audit_preflight.gd：跨模块冲突和恢复回归。

## Windows替换中断的专门保护

核对Godot 4.6官方Windows实现后，不能把其文件覆盖rename称为与Linux相同的原子操作。提交先验证并保留最近有效备份。若进程在主文件替换间隙退出，下一次启动检测到“主文件缺失、备份存在”，显示只读恢复界面，不创建空档。恢复采用大于当前/备份的修订号，保留原始文件或中断临时文件；本地模拟服务采取相同保护，并验证文件指纹防止旧窗口覆盖恢复结果。

模拟服务恢复前明确说明会回退备份后的聊天、公会、云版本和订单，影响整个本机模拟服务；普通游戏档与虚拟设备缓存不改动。恢复按钮在登录前的错误页面也可用。模拟云载荷采用完整浮点精度JSON保存。

验证在Linux中构造同样的“主文件缺失而备份完整”状态，测试保护、失败重试、恢复、继续战斗及订单回执去重；这是故障状态验证，不是Windows真机断电/崩溃测试。实际Windows执行仍待验证。

实现依据：[Godot 4.6 Windows目录实现](https://github.com/godotengine/godot/blob/4.6.3-stable/drivers/windows/dir_access_windows.cpp)。
