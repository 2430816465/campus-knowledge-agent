# 洪荒众仙府 0.4：灵装与战力

## 可玩范围和机制依据

这是原生 Godot、离线测试版本的原创灵装系统。采用五部位循环：固定生命灵花、固定攻击天羽，以及可变主词条的时砂、玄觞、道冠；副词条最多四条，强化每四级新增或随机强化一条，二件/四件套效果直接进入战斗。

五部位与六部位是不同规则，本版本选定五部位。不是两个商业游戏系统逐项完全复刻，也不使用其名称、图标或美术。原作特有的元素精通/元素充能未被伪装为有效词条，本作将速度、通用伤害和治疗等实际支持的战斗属性加入公开词条池。

HoYoverse 官方的 [Information on Artifact Farming](https://support.hoyoverse.com/hc/en-us/articles/50333983166233-Information-on-Artifact-Farming)（核对日期 2026-10-06）明确说明获取与强化采用随机概率。该文章没有给出完整权重、各级主词条表或副词条数值。下面的权重、数值、经验、回收率、套装效果与战力公式均为本项目公开设计，不宣称是对方游戏未公开算法。

唯一运行配置是 `data/equipment-rules.json`，所有数值均由原生 `GameEquipment` 读取。

## 获得与背包

- 正常主线真实战斗胜利后结算一件。试用战斗和手动旧版 `settleVictory` 辅助命令不发装备。
- 秘境完整通关在正式结算时获得两件；中断或失败不发完整通关装备。
- 固定奖励可以指定星级、套装或部位，其余字段继续随机。角色挑战由经济层使用相同胜利结算接口。
- 主线 1–4 关：三星 65%、四星 30%、五星 5%。5–8 关：25%、60%、15%。9–12 关：0%、45%、55%。
- 随机部位各 20%；六套套装各 1/6。不存在看时间、点预览、换角色改变本次掉落的机制。
- 背包最多 500 件。正式奖励遇到背包已满，每个溢出掉落转化为 100 灵石，并在结果中分别记录到账与因灵石上限未到账数量；不会卡住胜利结算。
- 同一件只能装备在一个角色的对应部位。给另一角色使用前先卸下；替换当前部位不会销毁旧装备。
- 锁定、收藏和正在装备中的灵装都不能分解或作为材料。锁定与收藏不阻止合法强化。

## 主词条与副词条

| 部位 | 主词条与权重 |
| --- | --- |
| 灵花 | 固定数值生命 100% |
| 天羽 | 固定数值攻击 100% |
| 时砂 | 生命加成 26%、攻击加成 26%、防御加成 26%、速度 22% |
| 玄觞 | 生命加成 19%、攻击加成 19%、防御加成 19%、通用伤害加成 43% |
| 道冠 | 生命/攻击/防御加成各 22%；暴击率/暴击伤害各 10%；治疗加成 14% |

三星初始 1 或 2 条副词条；四星初始 2 或 3 条；五星初始 3 或 4 条。较少条数 80%、较多条数 20%。各等级上限分别为 +12、+16、+20。

副词条候选为数值生命/攻击/防御，生命/攻击/防御加成，速度，暴击率，暴击伤害。暴击两项的抽取权重各 6，其余各 10。先排除主词条和已有副词条，再对剩余权重归一化。因此副词条不重复，也不会和主词条同名。

每次获得或强化词条抽取四档之一，四档各 25%。五星的单次值如下；四星乘 0.75，三星乘 0.5。计算保留到六位小数，界面百分比显示一位小数。

| 副词条 | 四档单次增量 |
| --- | --- |
| 数值生命 | 12 / 14 / 16 / 18 |
| 数值攻击 | 2 / 3 / 4 / 5 |
| 数值防御 | 1 / 2 / 3 / 4 |
| 生命加成、攻击加成 | 2.9% / 3.3% / 3.7% / 4.1% |
| 防御加成 | 3.6% / 4.1% / 4.6% / 5.1% |
| 速度 | 1 / 1.5 / 2 / 2.5 |
| 暴击率 | 1.9% / 2.2% / 2.5% / 2.8% |
| 暴击伤害 | 3.8% / 4.4% / 5.0% / 5.6% |

+4、+8、+12、+16、+20（未超过星级上限时）分别判定一次。当前不足四条就新增一条；满四条则各 25% 概率选中一条强化。某条可以连续被强化，没有保底补偿或按战力修正概率。

主词条每一级确定性增长。五星起点→+20：生命 32→320，攻击 5→45，生命/攻击加成 7%→46.6%，防御加成 8.7%→58.3%，速度 3→15，暴击率 4.7%→31.1%，暴击伤害 9.3%→62.2%，治疗加成 5.4%→35.9%，伤害加成 7%→46.6%。本版本以线性表插值；四星/三星在自己的等级区间乘各自倍率。

## 强化、喂养与分解

淬灵精华由工坊加工：30 灵石、8 灵材，45 秒产出 2 个，先进入工坊仓库，领取后可用。

每个精粹提供 100 装备经验。升至下一级 L 的经验为：

- 三星：10 × (20 + 8L)
- 四星：10 × (30 + 8L)
- 五星：10 × (40 + 8L)

从 +0 升满的累计经验/只用精粹的数量为：三星 8640/87，四星 15680/157，五星 24800/248。灵石手续费为实际投入经验 × 0.05，向上取整。精粹不可拆分，因此等级之间可以保留少量剩余经验。强化经验暴击关闭；随机的是四级里程碑的副词条结果。

喂养未保护的灵装，获得三星/四星/五星基础 100/200/300 经验，加其已投入经验的 80%，向下取整。预览清楚展示会消耗的材料、经验、实际最终等级、灵石和精粹。投入超过最高等级的经验按整 100 返还精粹，不足 100 的部分会在预览和结果中明确列为损失。分解则得到星级基础 1/2/3 个精粹，加已投入经验的 80% 折算为整颗精粹。

精粹背包上限 999；分解/经验返还会溢出的操作整体拒绝。一次操作内不能重复选中同一件材料，不能将目标自身当材料。使用一键推荐不会挪用其他角色装备。

## 战力与战斗

装备汇总使用独立字段 `equipmentStats`，在入场时固定为快照。装备与套装会改变真实生命、攻击、防御、速度、暴击、伤害与治疗。副本中更换/强化外部装备不会偷偷改已开始战斗。

基础生命/攻击/防御先按旧版等级与灵宝成长取整，最终属性为 `round(基础 × (1 + 装备百分比) + 装备固定值)`；速度为 `max(1, 基础速度 + 装备速度)`。暴击率默认 0，上限 100%；暴击伤害为正常伤害之外额外 `50% + 装备暴击伤害`。无装备时保持原有战斗随机序列；不存在无来源的基础 5% 暴击。

面板战力公式：

`round(生命×0.22 + 攻击×3×(1+暴击率×暴击伤害)×(1+伤害加成) + 防御×2 + 速度×1.5 + 攻击×治疗加成 + 技能贡献)`

技能贡献为 `攻击×技能倍率÷max(1,冷却)`，达到分支开启等级或已永久开启分支时乘 1.15。队伍战力是队员之和。战力是快速参考，未完整计算阵容配合、连锁效果、控制时机、前后排和操作；它不控制胜负。一键推荐逐部位比较实际战力，不保证全局最佳套装组合或最优打法。

## 原子性、存档与校验

- 独立的持久化 `equipment.randomState`，与召请、战斗和秘境随机流互不推进。刷新 UI、排序、筛选和强化预览不抽随机数。
- `GameEquipment.command` 先复制状态，检查成本/保护，完成全部变化并验证后才提交；`GameStore` 再对完整游戏状态原子落盘。存档失败保留旧资产、旧词条和旧随机状态。
- 正式战斗奖励使用唯一 `rewardId` 记账。相同奖励重复结算返回第一次结果，不再掉落。可选命令 `txid` 会保存原始参数及结果；同 ID 不同操作拒绝。
- 存档保留每条词条的离散档位和每个四级强化记录。校验主词条所属部位、等级经验、四级里程碑顺序、每条数值与档位合计、唯一穿戴、背包上限、随机序列和编号。
- 普通档/展示档使用不同完整存档。展示档中的装备、掉落和强化不会进入普通档；导入展示档到普通档由存储层拒绝。
- 本地离线档不是联网防作弊服务：知道源码并自行修改文件的人仍可构造新的合法数据。这里保证的是游戏内事务一致性和损坏检测，不宣称服务器级安全。

经济层转发命令：`equipArtifact`, `unequipArtifact`, `lockArtifact`, `favoriteArtifact`, `enhanceArtifact`, `salvageArtifacts`, `equipBestArtifacts`。正式胜利内部调用 `reward_drops(state,reward_id,options,count)`；没有公开 `grantArtifact` 免费领取命令。

测试：`godot --headless --path . --script tests/test_equipment.gd`。覆盖 600 个种子、所有星级/部位、升级到上限、实际付费与原子拒绝、随机序列重放、重复奖励、保护材料、真实套装属性、战斗属性一致、保存失败重试、存档往返以及普通/展示隔离。
