# Godot 原生经济与经营

## 实际实现

`GameEconomy` 与 `GameExpedition` 为原生 GDScript，不调用 JavaScript、浏览器或旧版规则服务。不可变参考位于相邻 legacy-v03，旧源文件未改动。旧版稳定 ID 与 camelCase 存档字段保留。新 Godot 内容放在 `data/godot-rules.json`，装备与新增人物由独立 JSON 配置提供。

- 常驻角色池现为 50 位；原 14 位保持 ID、已得收藏和历史记录。
- 根据后续需求调整为角色专池：五星基础 0.6%、四星 5.1%、三星 94.3%，90 抽内五星、10 抽内四星或以上。档内等权，没有武器混池或 UP 歪池；不宣称复刻他作未公开的完整概率模型。
- 每抽基础 1 道缘；重复五星额外 8、四星额外 3、三星额外 1。兑换 100/40/20。心愿仅显示兑换缺口，不改变概率。
- 原 12%/20 抽规则的历史结果、道缘、已拥有角色不重新计价。旧 pity 数值保留为新五星保底已累计次数；新增四星保底从零开始。抽卡规则单独标记版本。
- 新正常档仍仅哪吒、黄飞虎、比干和 12 符。主线第 2/3 节点四位、五位和结缘自选保证不变。
- 20 级培养、永久分支解锁、免费真实台账退款、三段灵宝修复、三套编队、驻府和上阵并存完整保留。
- 原 7 类建筑，加藏珍库、灵石矿、炼宝台，共 10 类。24 个真实地块分为三个区域，每区八块；原 p0–p8 ID 保留，p9–p23 需实际资源扩建。扩建仍受章节核心区域门槛约束。
- 藏珍库每级增加 2000 待领资源容量、50 物品容量。施工不提前得收益，升级期间保留上一等级容量。
- 灵石矿每级基础每分钟 12 灵石；实际时间生产，先入设施待领仓。
- 炼宝台 30 灵石+8 灵材/45 秒产出 2 宝器精粹，驻府与设施升级只影响新工单。精粹用于真实装备强化。
- 原生产预扣、满仓暂停、退款容量拒绝、来源分账、移动不损失工单、离线 12 小时收益窗口和时间倒退保护保留。
- 每个 command 先在临时草稿推进时间；只有后续操作和保存成功才发布。UTC 日常不会因跨日后先点培养而记入旧日。
- 日常三目标及每日一次汇总符，与新增签到分开。签到为累计 7 天循环，按 UTC 日期去重，不要求连续、不处罚漏签。
- 新本地奖励信和成长活动具明确配置及稳定领取 ID。它们不是联网收件箱或真人运营消息。
- 挂机派遣为最多三条单次计时任务，5 分钟、30 分钟、12 小时；到期停止，不因晚领取无限累积。同一神仙不重复派遣，仍可上阵或驻府。
- 灵石/灵材商店、UTC 每日兑换限制、修为卷/灵药匣/精粹包实际使用效果。无真实货币交易。
- 每位已结缘角色有三阶万仙试炼，要求主试角色在当前队伍且满足等级/主线条件。复用真实战斗与固定丹药票据；只领取本角色本阶一次性奖励，不冒充主线首通。
- 主线正常胜利掉 1 件真实随机灵装；完整秘境回府掉 2 件；角色试炼胜利掉 1 件。装备实例、独立随机流、来源回执、满包转换、强化、回收与战斗属性由 `GameEquipment` 负责。
- 主线、秘境、角色试炼在入场冻结装备属性，战外换装不改变已开始的战斗。结果核对冻结快照。
- 本地模拟回执只接受绑定 mockAccount/mockRealm 的非展示分区，按回执 ID 去重；GameStore 必须先检查模拟服务中的回执。不是支付或账号服务。

## 配置、历史与保存边界

- `data/game-data.json` 保留原 content/economy/expedition 常量与初始/展示快照。
- `data/godot-rules.json` 提供扩建、建筑、配方、签到、商店、派遣、试炼和新卡池规则。
- 新炼宝台工单使用 `godot-economy-1` 冻结历史成本/产物表；原 v0.1/v0.2/v0.3 工单继续按旧独立历史表校验。
- `GameEconomy.command(state, name, args, now)` 返回 `{ok,error,data}`。自身也使用完整草稿，拒绝操作不半扣款或半发奖。GameStore 再执行验证、备份、落盘、发布。
- `advance`、所有查询与计时均使用毫秒时间戳；查询不偷偷写入状态。随机流独立于画面、声音和帧率。
- `validate_state` 检查收藏/编队、连续主线、核心、区域、建筑及唯一岗位、历史工单、设施仓与总仓、修复来源、日常、保底、试炼、商店、挂机、装备及秘境账本。
- `migrate_state` 支持 V1/V2/V3；保留额外字段，旧缺失投入用冻结 V1 价格补台账，无升级赠礼。冲突地块按稳定建筑 ID 安置，无空位保留待安置设施并暂停施工/生产时钟。
- 六种展示起点独立，只有明确创建展示档才补齐现有全部角色。普通旧档迁移不补全角色。展示/模拟标记不是防编辑签名。
- 本地存档和时钟可被用户修改。本实现是可靠性校验，不是服务端反作弊，也不访问旧浏览器 localStorage。

## 验证证据

执行环境：Godot 4.6.3，Linux，原生 headless 测试。HOME 和 XDG 三目录定向本工程 runtime-home。未将逻辑测试叫作 UI 或手机验收。

- `tests/test_economy.gd`：576 检查通过，覆盖两条保底、十连失败/重复交易/随机源失败、退款、分支、产线、移动、离线、十类建筑、扩建、签到、商店、道具、真实角色试炼、迁移和损坏结构。
- `tests/test_economy_flow.gd`：1493 检查、54 场真实战斗胜利，三条正常新档流程均通过。杨戬、赵公明、云霄三种保证自选；仅得到初始哪吒重复卡，不依赖抽卡好运。生产、研究、第一场手动、三章首领、双秘境、引雷双用途、灵宝二段、主线丹药、真实装备掉落、移动/驻府/升级、原生保存与刷新。
- 完整流程只注入隔离时钟与确定随机，不给开发资产、不手写通关标记、不用展示导入、不用扫荡。证据在 `Godot-ordinary-flow-evidence.json`。
- `tests/test_expedition.gd`：475 检查通过，包括与原 TypeScript 固定种子候选/战斗种子的精确对照、18 场真实秘境胜利和两次真实失败重试。
- 储存、装备、战斗、地图和界面各有独立测试与文档，查看其当前结果；本文件不替代那些验收。

运行示例：

```sh
HOME="$PWD/../runtime-home" \
XDG_DATA_HOME="$PWD/../runtime-home/data" \
XDG_CONFIG_HOME="$PWD/../runtime-home/config" \
XDG_CACHE_HOME="$PWD/../runtime-home/cache" \
/opt/godot/4.6.3/Godot_v4.6.3-stable_linux.x86_64 \
 --headless --path . --script tests/test_economy.gd
```

## 独立审查修复（2026-10-06）

角色试炼已有票据现在先按冻结快照恢复，再考虑新入场条件。已入场后重置主试等级、移出当前队伍或换携带丹药，都不阻断原挑战，且不重复扣药。不同角色/阶数的挑战仍要求先结束原票据。新增真实战斗回归和 JSON 恢复验证。

扩展规则 JSON 在载入时统一正规化整数，避免 Godot 将配置数值当浮点、存档恢复后当整数，造成派遣/炼宝工单/角色试炼的相同奖励快照被误判。新增三者同时进行的原生 GameStore 编码/解码回归，逐字段保留承诺与资产。完整普通档流程重跑仍为 1493 检查、54 场真实胜利，全部通过。
